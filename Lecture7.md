# Доповідь : Generics у .NET: мотивація, синтаксис та обмеження

## 1. Приклади використання узагальнених колекцій

* **`List<T>`:** Динамічний масив для зберігання впорядкованих елементів без розпаковки типів (boxing/unboxing). Наприклад, `List<string> cities` дає змогу працювати з рядками прямо без ручного приведення типів.
* **`Dictionary<TKey, TValue>`:** Структура даних «ключ-значення» для швидкого пошуку об'єктів за унікальним ключем. Наприклад, `Dictionary<int, Student>` забезпечує миттєвий доступ до студентів за їхнім ID.
* **`Queue<T>` та `Stack<T>`:** Узагальнені реалізації класичних структур даних (FIFO та LIFO), які забезпечують чітку типбезпеку при черговості обробки елементів.

## 2. Generics у LINQ та фреймворках

* **LINQ (Language Integrated Query):** Усі методи розширення (`Where`, `Select`, `FirstOrDefault`) працюють з інтерфейсом `IEnumerable<T>`, що дозволяє створювати універсальні запити до будь-яких джерел даних із збереженням типбезпеки на етапі компіляції.
* **Entity Framework Core:** Клас `DbContext` використовує `DbSet<TEntity>` для відображення таблиць бази даних на C#-класи, а паттерн `Repository<T>` дозволяє реалізувати універсальну логіку для CRUD-операцій без дублювання коду.

## 3. Переваги Generics при розробці власних бібліотек

* **Повторне використання коду:** Один узагальнений клас або метод (наприклад, `InMemoryRepository<T>`) може працювати з будь-якими сутностями в системі.
* **Безпека типів (Type Safety):** Компілятор перевіряє типи під час компіляції, запобігаючи виникненню `InvalidCastException` під час виконання програми.
* **Обмеження типів (where constraints):** Дозволяють накладати чіткі вимоги на параметри типів (наприклад, `where T : class, IEntity, new()`), що надає доступ до необхідних методів та конструкторів сутності.
