# Доповідь: Винятки у .NET: базові патерни й retry  

# 1. Коли використовувати винятки, а коли повертати результат

Вибір між викиданням винятку (throw) та поверненням спеціального значення (null, bool, Result<T>) залежить від того, чи є ситуація очікуваною частиною бізнес-логіки.   

- Винятки (Exceptions) слід використовувати, коли:

- Виникає непередбачувана або критична помилка, яка порушує нормальний хід виконання програми (наприклад, відсутній файл конфігурації, втрачено з'єднання з базою даних, закінчилася пам'ять).   

- Порушено контракт методу (передано null туди, де це категорично заборонено — ArgumentNullException).

- Метод не може виконати те, що обіцяє його назва (наприклад, метод SaveOrder() не зміг зберегти замовлення через збій диска).

- Спеціальні значення (bool, null, Result<T>) краще повертати, коли:

- Ситуація є очікуваною та штатною частиною роботи програми (наприклад, користувач ввів неправильний пароль, товар не вдалося знайти у кошику, рядок не вдалося перетворити в число).   

- Перевірка відбувається дуже часто у циклах або високонавантажених ділянках коду (використання патерну Tester-Doer або Try-Parse).

# 2. Приклади сценаріїв для кожного підходу

Сценарій А: Повернення результату (патерн Try-Parse)

Користувач вводить дані з клавіатури. Помилка введення — це нормальна ситуація, а не збій системи.

```csharp
// Замість int.Parse() (який кидає FormatException), використовуємо TryParse:
string userInput = "abc";

if (int.TryParse(userInput, out int number))
{
    Console.WriteLine($"Введено число: {number}");
}
else
{
    Console.WriteLine("Некоректний формат числа. Спробуйте ще раз.");
}
```

Сценарій Б: Використання власного винятку (Custom Exception)

Користувач намагається зняти з банківського рахунку суму, більшу за поточний баланс. Це порушення бізнес-правила операції зняття.   

```csharp
public void Withdraw(decimal amount)
{
    if (amount > Balance)
    {
        // Кидаємо специфічний виняток, бо операція не може бути завершена
        throw new InsufficientFundsException(
            "Недостатньо коштів на рахунку.", 
            amount, 
            Balance
        );
    }

    Balance -= amount;
}
```

Сценарій В: Патерн Result<T> для бізнес-логіки

Використовується для реєстрації користувача, коли потрібно повернути зрозумілу причину відмови без генерації винятків.

```csharp
public Result<User> RegisterUser(string email)
{
    if (UserExists(email))
    {
        return Result<User>.Failure("Користувач з таким email вже існує.");
    }

    var newUser = new User(email);
    return Result<User>.Success(newUser);
}
```

3. Переваги та недоліки кожного підходу

Винятки (try-catch-finally)

Переваги:

- Чистота основного коду: Логіка успішного виконання не засмічується десятками перевірок if (error != null).

- Неможливість проігнорувати помилку: Якщо виняток не обробити, програма зупиниться з детальним стеком викликів (Stack Trace), що полегшує пошук багів.

- Передача деталей: Власні класи винятків дозволяють передавати додаткові властивості (наприклад, суму запиту та поточний баланс).   

Недоліки:

- Низька продуктивність при частому використанні: Створення об'єкта винятку та збір Stack Trace вимагають значних ресурсів процесора. Використовувати винятки для керування звичайною логікою (control flow) — погана практика.

Повернення спеціальних значень (bool, null, Result<T>)

Переваги:

- Висока продуктивність: Повернення false або об'єкта Result працює миттєво, без накладних витрат на перехоплення стека.

- Явність: Сигнатура методу одразу підказує розробнику, що операція може завершитися невдачею (наприклад, TryGetValue).

Недоліки:

- Ризик ігнорування помилки: Програміст може забути перевірити повернутий bool або null, що призведе до NullReferenceException пізніше в іншому місці програми.

- Громіздкість коду: Потрібно постійно писати перевірки if (!result.IsSuccess) на кожному рівні виклику методів.
