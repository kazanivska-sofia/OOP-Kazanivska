# Доповідь: "LINQ: основи і відкладене виконання"

# 1. Концепція відкладеного виконання (Deferred Execution)

Відкладене виконання означає, що LINQ-запит не виконується негайно в момент його оголошення. Замість цього створюється об'єкт запиту, який зберігає лише логіку обробки даних.

Фактичний виклик і обробка даних відбуваються лише тоді, коли ми починаємо перебирати результати (наприклад, у циклі foreach) або коли викликаємо метод негайного виконання.

Переваги відкладеного виконання:

Оптимізація: Запити можна комбінувати та оптимізувати перед фактичним виконанням.

Актуальність даних: Запит завжди обробляє найсвіжіші дані, які є в джерелі на момент ітерації.

Ефективність: Обробляються лише ті дані, які дійсно потрібні в даний момент.

Приклад відкладеного виконання:
```csharp
List<int> numbers = new List<int> { 1, 2, 3 };

// Запит оголошено, але ще НЕ виконано
var query = numbers.Where(n => n > 1);

// Змінюємо початкове джерело даних
numbers.Add(4);

// Запит виконується САМЕ ТУТ (під час ітерації)
foreach (var n in query)
{
    Console.WriteLine(n); // Виведе: 2, 3, 4 (включаючи додане число 4!)
}
```

# 2. Методи негайного виконання (Immediate Execution)

Негайне виконання відбувається тоді, коли метод LINQ повертає конкретне значення (наприклад, число, булеве значення) або агреговану колекцію (List, Array), а не IEnumerable<T>.

Основні методи негайного виконання:

Перетворення в колекцію: ToList(), ToArray(), ToDictionary().

Агрегатні функції: Count(), Sum(), Average(), Min(), Max().

Отримання одиничного елемента: First(), FirstOrDefault(), Single(), Last().

Приклад негайного виконання:

```csharp
List<int> numbers = new List<int> { 1, 2, 3 };

// Запит виконується НЕГАЙНО через виклик ToList()
var resultList = numbers.Where(n => n > 1).ToList();

// Змінюємо джерело
numbers.Add(4);

// Перебираємо вже збережений результат у пам'яті
foreach (var n in resultList)
{
    Console.WriteLine(n); // Виведе: 2, 3 (число 4 НЕ потрапило в результат)
}
```

# 3. Різниця між IEnumerable та IQueryable

Обидва інтерфейси використовуються для роботи з колекціями, але вони мають кардинальні відмінності у способі виконання запитів:   

IEnumerable<T> (LINQ to Objects):

Використання: Для обробки колекцій, які вже знаходяться в оперативній пам'яті програми (масиви, списки).   

Місце виконання: Фільтрація та сортування виконуються на стороні клієнта (в пам'яті C#).   

Особливість: При роботі з базами даних спочатку завантажує всі записи в пам'ять, а вже потім здійснює фільтрацію.   

IQueryable<T> (LINQ to SQL / Entity Framework):

Використання: Для роботи із зовнішніми джерелами даних (базами даних, SQL).   

Місце виконання: Запит транслюється в мову бази даних (наприклад, SQL) і виконується безпосередньо на сервері БД.   

Особливість: Завантажує в програму лише ті дані, які вже пройшли фільтрацію на сервері.   

Чому важливо розуміти цю різницю?

Якщо використовувати IEnumerable<T> при роботі з Entity Framework, програма витягне всю таблицю з бази даних у оперативну пам'ять C#, і лише потім відфільтрує її. Це може спричинити перевитрату пам'яті та зависання системи.   

Використання IQueryable<T> дозволяє сформувати та оптимізувати SQL-запит безпосередньо на сервері бази даних, завантажуючи в програму лише потрібний результат.
