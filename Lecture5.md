# Доповідь: Поліморфізм у патернах: куди він веде

## Вступ
Поліморфізм дозволяє працювати з об'єктами різних типів через спільний інтерфейс, автоматично визначаючи потрібну поведінку під час виконання програми. Це фундамент для створення гнучких патернів проєктування.

---

## 1. Поліморфізм у класичних патернах

* **Strategy (Стратегія):**
  Описує спільний інтерфейс для алгоритмів (наприклад, `IPaymentStrategy`). Конкретні класи реалізують його по-своєму. Головний код працює з інтерфейсом і не залежить від деталей реалізації.

* **Factory Method (Фабричний метод):**
  Використовує поліморфізм для створення об'єктів. Базовий клас оголошує фабричний метод, а похідні класи перевизначають його, повертаючи конкретні екземпляри продуктів.

* **Observer (Спостерігач):**
  Видавець зберігає список спостерігачів через спільний інтерфейс (`IObserver`). При зміні стану видавець викликає поліморфний метод сповіщення у кожного підписника.

---

## 2. Як поліморфізм спрощує реалізацію

1. **Усунення умовних операторів:** Замість складних конструкцій `if-else` або `switch` використовується один поліморфний виклик методу.
2. **Розширюваність без зміни коду:** Додавання нових варіантів (нових стратегій чи спостерігачів) виконується створенням нового класу без редагування існуючого коду.

---

## 3. Переваги в архітектурі великих застосунків

* **Слабке зв'язування (Low Coupling):** Модулі залежать від абстракцій, а не від конкретних реалізацій.
* **Принцип відкритості/закритості (Open/Closed Principle):** Код відкритий для розширення, але закритий для модифікації.
* **Зручність тестування:** Легко підміняти реальні залежності на тестові макети (Mocks).
